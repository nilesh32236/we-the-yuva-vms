# Fix Summary — Issue #187 (Audit: pwa-offline)

## What Was Done

Fixed the 8 PWA/offline findings from the audit: push-subscription churn, authenticated API data leaking into the offline runtime cache, a no-op connectivity poll, an overlay that covered the top nav, a dead-code offline retry, an out-of-sync committed SW artifact, swallowed install failures, and missing image/API offline fallbacks.

## Approach

The audit's two **important** findings were fixed at their root cause and hardened at the call site:

- **Push churn**: `subscribe`/`unsubscribe` in `usePushNotifications` were plain closures recreated every render, so the auto-subscribe effect in `PushSubscriber` re-fired on every render and each call unsubscribed + re-subscribed. They are now wrapped in `useCallback` (stable unless `permission` changes), and `PushSubscriber` additionally guards the background auto-subscribe with a ref keyed on `user.id` + permission so it can only run once per user.
- **Auth-sensitive offline caching**: `app/sw.ts` was passing Serwist's `defaultCache` straight through, which writes authenticated GET responses (notifications, `/users/me`, profile, dashboard, events, admin, etc.) into the persistent `apis` runtime cache for 24h. The `NetworkOnly` rule is now prepended to `runtimeCaching` for **all** same-origin GET `/api/v1/*` requests (inverted from a denylist to a safe-by-default allowlist) so auth-scoped and PII responses are never persisted — this also keeps `/api/v1/health` from being answered from the SW runtime cache. A new `LOGOUT` message handler purges all non-precache caches, and `auth-context.tsx`'s `logout()` posts that message; when no SW is controlling the page (first load / waiting update) it falls back to posting to the active registration. The `LOGOUT` handler deletes every cache except the precache (which contains only the app shell/static assets), so both the old `api-responses` and the current `apis` cache names are covered.

The six **minor** findings were fixed in place:

- `NetworkStatusIndicator`'s 10s poll now performs a real `fetch('/api/v1/health', { cache: 'no-store' })` probe with an abort timeout matching the 10s interval, and only downgrades to the "Connection Lost" state after **two consecutive** probe failures so a slow-but-alive backend (HF Spaces cold start) is not flagged offline; the toast was moved below the sticky TopNav (`top-…+4.5rem`, `z-20`) so it can no longer cover header controls.
- The offline retry's dead `offline-intended-destination` sessionStorage branch was replaced with a working channel: when Serwist's fallback serves `/offline` for a failed navigation, the SW records the original `request.url` into the `offline-navigation` Cache Storage and replies to a `GET_INTENDED_DESTINATION` message from the `/offline` page; the retry button now navigates to that URL (falling back to `router.back()` only when none exists). The async reply is wrapped in `event.waitUntil(...)` so the SW stays alive until the destination is delivered.
- The committed, git-tracked `frontend/public/sw.js` build artifact (built with `skipWaiting:true` and an older cache config) was removed from the index and ignored via `.gitignore`; the SW is served by the `app/serwist/[path]/route.ts` route at build time, so the source can no longer diverge from the artifact. Verified the compiled SW omits `skipWaiting` so the "New Version Available" prompt flow is preserved.
- `PWAInstallBanner.handleInstall` now surfaces rejected `install()` calls via `console.error`, `Sentry.captureException`, and a destructive toast instead of an empty catch.
- `app/sw.ts` fallbacks now serve the precached `/icons/offline-placeholder.svg` (the actual location of the placeholder asset, matching the precache key) for `request.destination === 'image'`, so offline users get a placeholder instead of broken-image icons.

Follow-up review refinements (already folded into the bullets above):

- The `NetworkOnly` matcher was inverted to cover **all** `/api/v1/*` GET requests (previously only `/auth`, `/users/me`, `/notifications`, `/profile`, `/dashboard`), so `/api/v1/health` and other authenticated endpoints (events, opportunities, admin, etc.) can no longer be served from the SW runtime cache — safe-by-default for future endpoints too.
- The offline image placeholder fallback now points at `/icons/offline-placeholder.svg`, the actual precached key, so `matchPrecache` resolves it.
- The `GET_INTENDED_DESTINATION` reply is wrapped in `event.waitUntil(...)` so the SW cannot be terminated before the message is posted.
- `logout()` falls back to the active registration when `navigator.serviceWorker.controller` is null.
- The push guard is also set on the manual opt-in path and cleared on subscribe failure; `subscribe()` now propagates errors so failures are observable and retryable.
- The health probe timeout was raised to match the 10s interval and requires two consecutive failures before showing the offline banner.

### Iteration refinements (PWA/offline follow-up)

- **Offline fallback & client-side navigation (sw.ts)**: Clarity added around why `/offline` is served only for `request.destination === 'document'`. An in-app App Router `<Link>`/`router.push` transition fetches flight data (RSC header, empty destination); when that payload fetch fails offline, Next.js's router falls back to an MPA (full-page) navigation of the intended URL (`fetch-server-response.js` in `next/dist`), which arrives at the SW as a document request — so in-app taps are already covered by the fallback and the destination recorded is the tapped route. Serving the `/offline` HTML directly to an RSC request is deliberately avoided because the router expects flight data there and an HTML body breaks the transition. Extracted `recordIntendedDestination` helper. No runtime-caching or navigation behavior changed.
- **Health probe accuracy (`NetworkStatusIndicator.tsx`)**:
  - The probe now reads `res.ok`, so a live backend returning 5xx (e.g. an HF Spaces reverse-proxy 502 during a restart) is treated as offline instead of silently healthy. Only a 2xx counts as success and resets the failure counter; any non-2xx counts toward the two-consecutive-failure threshold.
  - Recovery detected by the probe alone now surfaces the same 'Back Online' toast + haptic as the browser `online` event, gated on the banner actually having been shown (`consecutiveFailures >= 2`, i.e. a real offline→online transition) so the toast is not spammed every 10s. `handleOnline` resets the probe failure counter so the two detection paths don't double-show the toast.
  - An `inFlight` guard serializes probes, so a slow-but-alive backend whose fetch runs up to its 10s abort can no longer overlap with the next tick and double-count toward the offline threshold.
  - The probe now skips when `navigator.onLine` is already `false` (the `online`/`offline` events own that state) and when the tab is hidden/backgrounded; a `visibilitychange` listener triggers an immediate probe when the tab becomes visible again. This removes needless per-tab backend traffic and background probing.

## Key Changes

- `frontend/hooks/usePushNotifications.ts` — `subscribe`/`unsubscribe` memoized with `useCallback` (`[permission]` / `[]`) so identity is stable across renders.
- `frontend/components/PushSubscriber.tsx` — added a ref guard so the background auto-subscribe runs once per user+permission; the guard is also set on the manual opt-in path (preventing the permission-change re-fire from re-subscribing) and cleared on failure so a later attempt can retry.
- `frontend/app/sw.ts` — prepended a `NetworkOnly` rule for all `/api/v1/*` GET requests to `runtimeCaching`; added `LOGOUT` (cache purge) and `GET_INTENDED_DESTINATION` message handlers; records the failed navigation URL when serving the `/offline` fallback (extracted into a `recordIntendedDestination` helper, with a comment documenting how in-app App Router taps reach this fallback via Next.js's MPA fallback); added an image fallback to `/icons/offline-placeholder.svg`.
- `frontend/lib/auth-context.tsx` — `logout()` now posts a `LOGOUT` message to the active service worker (falling back to the active registration when no controller exists) so cached authenticated data is purged across sessions.
- `frontend/components/shared/NetworkStatusIndicator.tsx` — real `/api/v1/health` probe with a 10s timeout and a two-consecutive-failure threshold; `res.ok` is checked so non-2xx responses count as failures; probe-detected recovery shows the 'Back Online' toast (gated on a real transition, no 10s spam); an `inFlight` guard serializes probes to prevent overlap; the probe is skipped while `navigator.onLine` is false or the tab is hidden; toast repositioned below the header and z-index lowered below the nav.
- `frontend/app/offline/page.tsx` — retrieves the intended destination from the SW via `GET_INTENDED_DESTINATION` and retries it; removed the dead `sessionStorage` branch.
- `frontend/components/shared/PWAInstallBanner.tsx` — install failures are now logged, reported to Sentry, and shown to the user via a destructive toast.
- `frontend/public/icons/offline-placeholder.svg` — new precached offline image placeholder (new file, served at `/icons/offline-placeholder.svg`).
- `.gitignore` + `git rm --cached frontend/public/sw.js` — the Serwist build artifact is no longer committed so source and artifact cannot drift.
