# Fix Summary — Issue #187 (Audit: pwa-offline)

## What Was Done

Fixed the 8 PWA/offline findings from the audit: push-subscription churn, authenticated API data leaking into the offline runtime cache, a no-op connectivity poll, an overlay that covered the top nav, a dead-code offline retry, an out-of-sync committed SW artifact, swallowed install failures, and missing image/API offline fallbacks.

## Approach

The audit's two **important** findings were fixed at their root cause and hardened at the call site:

- **Push churn**: `subscribe`/`unsubscribe` in `usePushNotifications` were plain closures recreated every render, so the auto-subscribe effect in `PushSubscriber` re-fired on every render and each call unsubscribed + re-subscribed. They are now wrapped in `useCallback` (stable unless `permission` changes), and `PushSubscriber` additionally guards the background auto-subscribe with a ref keyed on `user.id` + permission so it can only run once per user.
- **Auth-sensitive offline caching**: `app/sw.ts` was passing Serwist's `defaultCache` straight through, which writes authenticated GET responses (notifications, `/users/me`, profile, dashboard) into the persistent `apis` runtime cache for 24h. A `NetworkOnly` rule is now prepended to `runtimeCaching` for the auth-sensitive API path prefixes so those responses are never persisted, and a new `LOGOUT` message handler purges all non-precache caches; `auth-context.tsx`'s `logout()` posts that message. The `LOGOUT` handler deletes every cache except the precache (which contains only the app shell/static assets), so both the old `api-responses` and the current `apis` cache names are covered.

The six **minor** findings were fixed in place:

- `NetworkStatusIndicator`'s 10s poll now performs a real `fetch('/api/v1/health', { cache: 'no-store' })` probe with a 5s AbortController timeout instead of re-reading `navigator.onLine`, and the toast was moved below the sticky TopNav (`top-…+4.5rem`, `z-20`) so it can no longer cover header controls.
- The offline retry's dead `offline-intended-destination` sessionStorage branch was replaced with a working channel: when Serwist's fallback serves `/offline` for a failed navigation, the SW records the original `request.url` into the `offline-navigation` Cache Storage and replies to a `GET_INTENDED_DESTINATION` message from the `/offline` page; the retry button now navigates to that URL (falling back to `router.back()` only when none exists).
- The committed, git-tracked `frontend/public/sw.js` build artifact (built with `skipWaiting:true` and an older cache config) was removed from the index and ignored via `.gitignore`; the SW is served by the `app/serwist/[path]/route.ts` route at build time, so the source can no longer diverge from the artifact. Verified the compiled SW omits `skipWaiting` so the "New Version Available" prompt flow is preserved.
- `PWAInstallBanner.handleInstall` now surfaces rejected `install()` calls via `console.error`, `Sentry.captureException`, and a destructive toast instead of an empty catch.
- `app/sw.ts` fallbacks now also serve a precached `offline-placeholder.svg` for `request.destination === 'image'` (auto-precached from `public/`), so offline users get a placeholder instead of broken-image icons.

## Key Changes

- `frontend/hooks/usePushNotifications.ts` — `subscribe`/`unsubscribe` memoized with `useCallback` (`[permission]` / `[]`) so identity is stable across renders.
- `frontend/components/PushSubscriber.tsx` — added a ref guard so the background auto-subscribe runs once per user+permission.
- `frontend/app/sw.ts` — prepended a `NetworkOnly` rule for auth-sensitive `/api/v1/*` GET endpoints to `runtimeCaching`; added `LOGOUT` (cache purge) and `GET_INTENDED_DESTINATION` message handlers; records the failed navigation URL when serving the `/offline` fallback; added an image fallback to `offline-placeholder.svg`.
- `frontend/lib/auth-context.tsx` — `logout()` now posts a `LOGOUT` message to the active service worker so cached authenticated data is purged across sessions.
- `frontend/components/shared/NetworkStatusIndicator.tsx` — real `/api/v1/health` probe with timeout; toast repositioned below the header and z-index lowered below the nav.
- `frontend/app/offline/page.tsx` — retrieves the intended destination from the SW via `GET_INTENDED_DESTINATION` and retries it; removed the dead `sessionStorage` branch.
- `frontend/components/shared/PWAInstallBanner.tsx` — install failures are now logged, reported to Sentry, and shown to the user via a destructive toast.
- `frontend/public/icons/offline-placeholder.svg` — new precached offline image placeholder (new file).
- `.gitignore` + `git rm --cached frontend/public/sw.js` — the Serwist build artifact is no longer committed so source and artifact cannot drift.
